# LIFE 0.3 — планер для GitHub Pages + Firebase Firestore

## С чего начать

Это доработанная версия LIFE_v0.2.html. Внешний вид и разделы сохранены.
Добавлены вход по почте и паролю, синхронизация отдельных записей, локальная очередь изменений, установка PWA и сохранение отметок ежедневного ухода.

Пакет уже содержит настройки вашего Firebase-проекта life-planner-d1fd1. Файл firebase-config.js заполнен. Начинайте с проверки Firebase и загрузки сайта на GitHub. Вход и чтение вашей настоящей базы во время подготовки не выполнялись.

## 1. Настройки Firebase уже заполнены

Этот шаг выполнен за вас. Ниже оставлена справка на случай смены проекта.

1. Откройте https://console.firebase.google.com/ и выберите созданный проект.
2. Нажмите шестерёнку рядом с названием проекта → Project settings.
3. На вкладке General прокрутите до Your apps и выберите своё веб-приложение со значком </>.
4. В SDK setup and configuration выберите Config, если такой выбор есть.
5. Скопируйте значения из блока `firebaseConfig`.
6. Откройте `firebase-config.js` из этого архива в текстовом редакторе.
7. Замените значения в кавычках вашими значениями. Сохраните файл именно с расширением `.js`.

Например, строка:

```js
projectId: "ВАШ_PROJECT_ID",
```

должна стать чем-то вроде:

```js
projectId: "life-planner-12345",
```

Не меняйте имена полей, запятые и фигурные скобки. Не вставляйте туда пароль от планера, ключ сервисного аккаунта или файл Admin SDK. Веб-настройки Firebase предназначены для использования в коде сайта; доступ к записям определяют Authentication и Firestore Rules.

## 2. Проверьте Firebase

- Authentication → Sign-in method → Email/Password включён.
- Authentication → Users: создан ваш пользователь с почтой и паролем.
- Firestore: создана база `(default)` в редакции Standard.
- Firestore → Rules: опубликованы правила из `firestore.rules` в этом архиве. Их можно скопировать целиком в редактор Rules и нажать Publish. Если вы уже вставили такие же правила на шаге 5, повторять не нужно.
- После публикации сайта добавьте `ВАШ-ЛОГИН.github.io` в Authentication → Settings → Authorized domains. Указывается домен без https и пути.

Файл `firestore.rules` на GitHub сам по себе правила не применяет: их нужно публиковать в Firebase Console.

## 3. Загрузите сайт на GitHub

1. Распакуйте ZIP в отдельную папку на компьютере.
2. Откройте созданный репозиторий `life-planner` на GitHub.
3. Нажмите Add file → Upload files.
4. Перетащите СОДЕРЖИМОЕ распакованной папки: файлы и папки `icons`, `vendor`.
5. Убедитесь, что `index.html` находится непосредственно в корне репозитория. Не загружайте один ZIP-файл вместо его содержимого.
6. Нажмите Commit changes.
7. Откройте Settings репозитория → Pages.
8. Source → Deploy from a branch; Branch → main; Folder → / (root); Save.
9. Откройте появившуюся HTTPS-ссылку. Она обычно имеет вид https://ВАШ-ЛОГИН.github.io/life-planner/.

Пакет использует относительные пути: подойдёт и для сайта в подпапке репозитория, и для корня собственного домена.
Собирать проект, устанавливать Node.js или запускать npm не требуется.

## 4. Войдите и проверьте синхронизацию

1. Откройте сайт при включённом интернете.
2. Введите почту и пароль пользователя из Firebase Authentication.
3. Дождитесь загрузки; добавьте тестовую задачу.
4. Дождитесь статуса «Сохранено в облаке».
5. Откройте сайт на другом устройстве и войдите тем же аккаунтом.
6. Убедитесь, что тестовая задача появилась. Проверьте также удаление.
7. После первой загрузки на устройстве дождитесь завершения загрузки офлайн-версии, затем отключите интернет и откройте сайт заново.
8. В уже открывавшемся аккаунте добавьте задачу без интернета. Подключитесь и дождитесь статуса сохранения в облаке. Проверьте задачу на другом устройстве.

Первый вход и первое получение записей на новом устройстве требуют интернета.
При первом запуске дайте приложению несколько секунд для сохранения файлов PWA.
Кнопка «Работать только на этом устройстве» открывает отдельное локальное хранилище. Оно не синхронизируется с аккаунтом автоматически.

## 5. Перенесите данные старой версии

1. Откройте СТАРЫЙ LIFE_v0.2.html в том браузере, в котором вы им пользовались.
2. Внизу страницы нажмите «Экспортировать резервную копию». Сохранится JSON-файл.
3. Откройте НОВЫЙ сайт и войдите в нужный аккаунт.
4. Если в нём уже есть важные записи, сначала экспортируйте и их.
5. Внизу нового планера нажмите «Импортировать копию» и выберите JSON старого планера.
6. Подтвердите замену данных и дождитесь «Сохранено в облаке».
7. Проверьте результат на другом устройстве.

Импорт ЗАМЕНЯЕТ записи в текущем аккаунте или локальном режиме. Автоматического объединения двух резервных копий нет.
Перед заменой дополнительно сохраняется локальная копия в браузере; основной надёжный способ восстановления — заранее скачать JSON.
Экспортированный JSON содержит личные записи. Загружать его в публичный репозиторий не нужно.
Данные браузера с адреса file:// сами не перейдут на адрес https://…: используйте экспорт и импорт.

## 6. Установите приложение

- Android + Chrome: меню → «Установить приложение» / «Добавить на главный экран».
- iPhone + Safari: «Поделиться» → «На экран Домой».
- Компьютер + Chrome/Edge: кнопка установки в адресной строке или в меню.
- Если браузер предоставляет автоматическую установку, внутри LIFE появится кнопка «Установить».

В браузерах без установки планер остаётся доступен как сайт.

## Как устроено хранение

- Записи лежат в `users/{uid}/records/{recordId}` в Firestore.
- Задачи, проекты, цели, привычки, события, записи коллекций и заметки хранятся отдельными документами.
- На устройстве сохраняются копия последнего состояния и очередь неподтверждённых изменений. Они разделены по проекту Firebase, пути сайта и аккаунту.
- Для этой копии используется localStorage. Постоянный кэш SDK Firestore намеренно не включён, чтобы не создавать вторую независимую очередь записей. Сам механизм Firestore работает через SDK; офлайн-копией управляет приложение.
- После возврата сети изменения отправляются по очереди. Статус «Сохранено в облаке» появляется после подтверждения записи сервисом.
- Удалённые записи оставляют техническую отметку об удалении — это предотвращает их возвращение со старого устройства.
- При одновременном изменении ОДНОЙ записи сохраняется последняя принятая облаком версия. Автоматического объединения текстов, этапов одного проекта или отметок одной привычки нет. Разные записи синхронизируются отдельно.
- Выход скрывает записи, но оставляет защищённую аккаунтом на уровне приложения локальную копию для следующего входа. Пользуйтесь этим режимом на личных устройствах. Очистка данных браузера удаляет локальную копию и ещё не отправленную очередь.
- Одновременное открытие одного аккаунта в нескольких вкладках одного браузера блокируется через Web Locks, когда браузер поддерживает этот API. На телефоне и компьютере одновременно работать можно. Если Web Locks недоступен, используйте одну вкладку на каждом устройстве.
- Исходные личные примеры проектов и целей в публичный код не включены. Вернуть их вместе со своими записями можно импортом.

## Если что-то не работает

| Что видно | Что проверить |
|---|---|
| «Подключение к Firebase ещё не настроено» | Заполнены ли реальные значения в firebase-config.js; нет ли синтаксической ошибки |
| «Не удалось войти» | Почта и пароль пользователя в Authentication → Users; включён ли Email/Password |
| «Нет доступа к Firestore» | Правила опубликованы, база `(default)` создана, projectId соответствует нужному проекту |
| Загрузка аккаунта не завершается | Интернет, блокировщики запросов к Google/Firebase, доступность сервиса и настройки Firestore |
| Режим уже открыт в другой вкладке | Закройте другую вкладку с этим аккаунтом/локальным режимом и обновите страницу |
| Данные не пришли на другой телефон | Одинаковый аккаунт, оба устройства онлайн, статус «Сохранено в облаке» на отправляющем устройстве |
| Нет установки / офлайн-режима | Открыт HTTPS-сайт, все файлы и vendor загружены, нет ошибок загрузки sw.js |
| На GitHub виден README вместо планера | Файл index.html лежит в корне, выбраны main и / (root) в Pages |

## Обновление сайта в будущем

Перед загрузкой любой новой версии файлов, включая изменение firebase-config.js, измените значение `VERSION` в начале `sw.js` на новое уникальное значение.
Например, `life-v03-20261116-1` → `life-v03-20261116-2`.
Иначе офлайн-кэш может продолжить показывать прежние файлы.
После загрузки новой версии сайт предложит «Обновить приложение». Сначала сохраните введённые тексты в формах.

## Проверка подготовленного пакета

Проверены синтаксис собственных JS-файлов, импорт копии v0.2, преобразование данных, локальное сохранение, очередь после перезапуска, изоляция аккаунтов, обработка запрета доступа, удаление и синхронизация на имитации Firebase API, а также список офлайн-файлов и пути в подпапке.
Настройки вашего проекта вставлены и проверены на соответствие присланному блоку. Вход в аккаунт и проверка синхронизации с настоящей базой должны выполняться после публикации.
Полноценная проверка интерфейса в браузере и установка на реальном телефоне в среде подготовки недоступны; выполните проверки из разделов 4 и 6 после публикации.
